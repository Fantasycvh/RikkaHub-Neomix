一 · 新皮肤档位：给 AppSkin 加「气质」，而不是只加圆角

现有三个内置皮肤（默认/紧凑/舒展阅读）全是 shapes + spacing 的数值变体，气质同源。第三轮的核心主张：每个新皮肤档位是一组完整 token 组合（palette + typography + shapes + spacing + motion + 聊天域 ChatAppearance），用户换皮肤 = 换整个气质。以下四档均为新增 AppSkinPreset，零架构改动，默认皮肤不动。

事实底座：AppSkin 全链路已就绪（typography/shapes/spacing/motion/palette/顶栏/抽屉/卡片），试用与回滚机制现成；ChatBubble.visible 已支持关气泡，纸质感档的「平铺」不需要新渲染器；缺口标注在各档「新增成本」行。

二 · 气泡几何自由度：一次数据类升级，补齐 SillyTavern 差距

竞品对照（第一轮调研 §4）指出的差距是气泡几何自由度：宽度、对齐、尾角。现状 ChatBubbleGeometry(radiusDp=16, paddingDp=8) 只有半径与内边距两个字段。提案：三个预设开箱即用，全部由现有字段加下方提案字段组合，无新渲染器。

事实底座：ChatLayout 已有 userAlignEnd / contentWidthFraction / messageGapDp；缺的是气泡级宽度上限与尾角。尾角用逐角圆角实现，不画 tail path（避免非连续曲率渲染问题）。
预设 1 · 经典尾角

用户气泡限宽 + 尾角收紧（聊天气泡的标志性轮廓），助手侧不变。

提案字段（ChatBubbleGeometry v2）说明
radiusDp保留，基准半径
tailCornerDp: Float?尾角收紧，映射到 userAlignEnd 侧的下角；null = 对称四角
maxWidthFraction: Float0.5 至 1.0，气泡内容宽度上限（现由 contentWidthFraction 全局管，气泡级补局部能力）；只影响测量宽度，不动增量渲染管线
paddingHorizontalDp / paddingVerticalDp拆分现有单一 paddingDp（现横竖同值 8dp，长文观感局促）
迁移现有 paddingDp=8 读取时拆成 8/8，序列化兼容；皮肤与 ChatAppearance 双层 overrides 机制不变

四 · motion token 表对照：从二值枚举到九档数值

现状 AppSkinMotion = EXPRESSIVE | STANDARD 只是个开关，仓内大量自定义动画仍手写 tween，时长各自为政（图标淡入 200ms、思维链短 tween、块淡入 240ms）。提案：引入 dsh-go 式数值 token 表作为第三档 TOKENS，先对齐存量散值，再逐步替换手写值。

可及性纪律照抄：系统「移除动画」开启时所有时长取 0（读 Settings.Global.ANIMATOR_DURATION_SCALE）；弹簧只喂位移/缩放，透明度永不越界；思维链短 tween 是已调优 perf 决策，不在替换清单内。

拍板点清单

  1. 皮肤档位取舍：四档全做，还是先做两档？建议先行：纸质感 + squircle（感知差最大、成本可控）；工程感与 iOS 档随后。
  2. serif 字体族：ChatFontFamily 是否新增 SERIF？内置字体（增加包体）还是系统衬线映射（GB 字重不可控）？建议系统衬线起步 + 皮肤 resources 已支持自定义字体导入兜底。
  3. squircle 连续曲率：值得为 HyperOS 档自绘 SmoothCorner path 吗？若不值得，该档降级为普通大圆角（28/32dp）仍成立。
  4. 气泡几何 v2 字段集：tailCornerDp / maxWidthFraction / padding 拆分三项是否按提案执行？
  5. IA 三件实施范围：先跑盘点表，首批只覆盖偏好设置 + 显示 + 模型设置三页？
  6. motion token 档：AppSkinMotion 加 TOKENS 档是否通过？收编散值首批清单（图标淡入 200→160）是否接受？
