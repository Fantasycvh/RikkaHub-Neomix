### 🔐 订阅登录重构（本版主功能：移植上游 OpenAI OAuth）

本版把上游 OAuth 订阅方案（`oauth` 模块 + 账号/额度体系 + 流式解码重构）整体移植到本仓，登录、凭据、额度从「设备码临时方案」换成可持续同步上游的架构：

- **ChatGPT 订阅**：改用 ChatGPT 官方 OAuth 登录（Custom Tabs 授权 + `127.0.0.1:1455` 本地回环回调），旧的「设备码登录」已移除；升级时自动把原订阅配置迁移成账号类 provider（**id / 名称 / 模型 / 代理 / 自定义头 / 重试 / 思考强度全部保留，无需重新登录**）。凭据以 `v1:` 密文落盘，401 时自动刷新并重试一次；刷新**并发安全**（同 provider 串行、写回前重读设置 + CAS，避免 refresh token 被并发打废）。
- **Grok 订阅（xAI）**：新增设备码登录，支持 SuperGrok 的模型目录与周 / 月用量；与聊天订阅同样受「订阅对话锁定」保护。
- **额度体系**：本仓旧「余额（BalanceOption）」整链路替换为 `ProviderQuota` / `QuotaQuery`——账号类展示用量窗口，API Key 类展示额度查询；**旧多源 / 表达式余额配置无损迁移**。新增「已用 / 剩余」两种展示口径切换（设置 → 界面 → 用量显示）。
- **订阅对话锁定**：历史里出现过某订阅提供商生成的消息后，该对话只能在该 provider 内换模型，避免把只有自家后端能解的加密推理丢给别家（轻则静默丢弃、重则 400）。
- **流式层重构**：四个 provider 统一 `StreamChunk` 解码路径（对齐上游 #1648），旧 `MessageChunk` 链路删除；Chat Completions / Responses / Claude / Google 全部走同一套容错与错误语义。
- **备份导入兼容**：可以直接导入上游 RikkaHub 的备份，其中的 `chatgpt` / `grok` 账号 provider 会正常落成账号类 provider（上游明文凭据按「无 `v1:` 前缀即明文」读取，导入即可用；首次刷新 / 保存后自动转密文）。单测 `UpstreamOAuthBackupImportTest` 4 例钉住。

### 🧩 修复与增强

- **Codex 订阅多轮 400 修复**：历史里带推理的请求会因 reasoning item 缺 `summary` 字段被 Codex 后端 400（表现为 `SSE stream failed without exception`）——现始终携带 `summary`（加密推理为空数组，不回放明文）。真机复测：原先必炸的「推理 + 工具」第二轮恢复正常。
- **SSE 失败信息可诊断**：兜底异常带上 HTTP 状态码（`… (HTTP 400)`），不再只能看到笼统断流。
- **订阅对话禁止编辑推理**：订阅账号的推理正文由服务端加密，回传的是 `encrypted_content` 密文，本地改的文本不会进入请求 ⇒ 编辑入口置灰并给出原因；`ContextPurifier` 也不会再改写这类块（保住加密历史）。
- **server-tool item 原样回传 + 全局会话头**：web_search / shell / image_generation 等服务端工具 item 按原样回传（Codex `store=false` 历史不再丢上下文），并补齐 `X-Session-ID` 会话头与 OpenRouter `session_id`（对齐上游 #2186）。

### ⚠️ 升级与降级

1. **升级前先备份**：设置 → 备份 → 立即备份（备份文件仍是旧格式，恢复时会走 V7 迁移把旧订阅条目转成账号类）。
2. **不建议降级**：V5 迁移后 `data_version = 5`，旧版本遇到 `chatgpt`/`grok` 类型会丢弃这些 provider（甚至整体解码失败）。
3. **必须降级时**：卸载后重装旧版本，再从升级前的备份恢复；直接覆盖安装旧 APK 会读到已迁移数据。
4. 降级后再升回本版：账号类 provider 会被保留，无需重复迁移。
