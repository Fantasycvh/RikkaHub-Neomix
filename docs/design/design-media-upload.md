# 媒体素材远端存储

## 决策变更

早期媒体移植因本仓没有 RemoteFileStore，遇到要求公网输入 URL 的请求会明确报错，未接入 S3。
2026-10-19 用户明确允许引入 RemoteFileStore 后，恢复上游上传链路及独立素材存储设置。
旧的安全边界仍保留：未配置或上传失败必须明确失败，不静默丢输入、不降级为本地路径。

## 配置与请求边界

- 上传配置使用 `Settings.uploadS3Config` / DataStore `upload_s3_config`，不复用备份 `s3Config`，也不自动复制凭据。
- 上传素材使用 HTTPS；不带协议时补 HTTPS。此限制仅作用于对第三方公开的素材 URL，不更改备份的内网 HTTP 支持。
- 只有 `requiresRemoteInputs && inputs.isNotEmpty()` 的请求上传；OpenAI multipart 和 SiliconFlow base64 输入继续本地处理，无需为画板配置 S3。
- VM 预检与服务端执行双重检查配置；上传失败/取消不可降级或吞掉。
- 链接只在当前内存请求中使用，不保存到媒体记录、通知或备份。

## 缓存与权限

- 对象 key 为 `rikkahub_uploads/<sha256>.<extension>`；同内容复用并重新签发链接。
- 默认签名 URL 有效期 24 小时，对象缓存保留 7 天。
- 清理仅在后续上传时顺带触发，不是独立定时任务；只删除上传前缀内超期对象，不能删除备份前缀。
- 配置切换清空远端状态缓存；错误分页响应不能导致清理死循环。
- 测试连接只验证 list 权限/连通性，不承诺具备上传、删除或第三方访问权限。
- 不要求将桶设置为公开 ACL。第三方可在签名链接有效期内访问相应图片/视频，请使用专用桶或最小权限凭据。

## 诊断与验证

- 画板保存/加载/导出增加应用内安全阶段日志，只记阶段、结果、字节数、MIME、异常类型，不记图片内容或凭据。
- 应用内日志和媒体错误消息需脱敏签名 URL 查询凭据。
- 自动测试的“无法加载图片”提示来自坏图负例：它故意传入不存在文件，验证禁止确认；不是草图保存失败。
- 真实云上传需要用户自行提供专用桶；本轮不自动连接或上传用户素材，也不主动调用收费生成接口。
