# 长文 P3：静态消息内部懒加载

在 P2 的显示投影上，将静态长消息的 header、正文安全区块、附件、翻译和 footer 放入聊天原有的同一个 LazyColumn。可见区才创建 BetterText 布局；完整原始消息和已解析文档仍保存在内存中。没有嵌套纵向 LazyColumn，也没有把编辑器移入 Lazy item。

## 启用范围

默认开启 `DisplaySetting.enableLongMessageLazyRendering`，可在通用设置关闭“长消息按需显示”。满足以下条件才准备静态文档：

- 标准布局 `builtin.standard`，用户或助手的普通消息；检查点、外部通知和子代理通知保留原路径。
- 当前角色的可见气泡为实色，或气泡隐藏/完全透明。渐变、纹理、噪声、玻璃等材质保留整条渲染。
- 至少一个原始 Text part 达到 8,000 UTF-16 字符。应用安全截断、视觉正则和公式归一化后，解析结果仍达到阈值，且至少有四个非空安全单元，才拆成列表行。

单个巨大段落、列表、代码或表格仍是原子单元，不按字符切断语法；数量不够时使用准备好的完整 MarkdownDocument 渲染，避免解析两次。超大单块的进一步优化属于 P5。

P3 只处理静态内容。本轮列表展示期间曾流式生成的助手回复继续沿用完整宿主，结束时不突然替换为准备占位符；重新进入静态会话后才允许拆分。其他历史长消息可在生成期间懒加载。流式区块增量更新和生成结束时的无跳动切换属于 P4。

## 准备与身份

`rememberStaticDocuments` 在 Default dispatcher 上一次性准备符合条件的文档，输入包含节点、当前消息、助手配置、折叠策略和截断提示。输入变化取消旧结果，匹配的既有文档直接复用；准备失败回退完整路径。准备期间显示 header、简短正文占位和 footer，所有操作仍指向完整节点。

正文使用 P2 已解析的 MarkdownRenderUnit，不截取源码重新解析。每个单元键包含节点 UUID、当前消息 UUID、原始 part 下标、准备 epoch 和解析单元 id。Header 使用节点 UUID 字符串维持原消息入口。没有内容 hash key。重新准备后的单元通过消息/part/显示源码范围恢复位置，分支变化保守回到节点入口。

列表行在安全边界上合并相邻小单元，每行最多八个单元、合计最多 1024 UTF-16 字符；超过该长度的原子单元独占一行。只合并现有节点和连续显示范围，不重新解析、不切开列表/围栏/HTML，不改变首块的全局位置。这样摊薄小段落的 Lazy 宿主开销。分组在后台准备时完成，静态正文不再重复建立消息分组或订阅布局注册表。

完整解析树和列表描述仍随当前会话/压缩窗口保留；本阶段减少的是离屏组合、测量和绘制，并非全文数据内存。首次完整解析仍有成本，准备时间不纳入稳态滚动帧指标。

## 列表索引与阅读位置

`ChatRenderIndex` 是逻辑消息到真实列表行的唯一映射，统一处理压缩检查点、正文单元和尾部按钮。引用、路由、预览搜索、发送后贴底和上下消息箭头都通过逻辑目标解析，不再猜测“消息数 + 5”。引用未选中分支时只定位所在节点，不自动切换分支；折叠历史中的目标先展开再定位。

存活的稳定键由 Compose 保持阅读位置。键因准备、分支或模式切换消失时，按节点/消息/part 和 parser-normalized 显示偏移尽力恢复。字号变化保留区块与像素偏移，不承诺同一字符落在屏幕同一点。`ChatListScrollController.Saver` 只保存七个短字符串：键、节点/消息身份、part、显示偏移、像素偏移及贴底状态，不把正文或 AST 放入 Bundle。

初次恢复等待异步准备完成；明确的跳转/发送命令优先，真实拖动取消待执行命令。生成贴底按实际最后行计算，且已经贴底时不重复请求布局，避免无内容变化时的布局循环。

## 外观与交互

标准长消息正文使用统一可用宽度，以便各行实色背景衔接；短行的长气泡可能比旧版 wrap-content 更宽。只有首尾单元有对应外圆角，单元间距画在气泡背景内部，中间不产生圆角或空白接缝。用户/助手对齐、字体、颜色、Markdown 组件和链接回调沿用现有实现。

Header、附件/思维链、翻译和动作栏保留原顺序和回调。一条消息只显示一个多选复选框；后续行保留同宽占位。打开动作、复制、推理编辑或翻译对话框时 pin 对应宿主，避免滚动回收关闭界面。

## 选择与完整复制

聊天视口使用一个有界 BetterSelectionContainer。每个长正文 part 的多个单元共享选择组；普通消息、其他 part 和附件内选择组保持隔离，拖动不会跨到无关消息。原有不在 SelectableContent 内的文本不会被全局宿主自动纳入选择。

普通长按/拖动仍按已布局文本选择，跨 Markdown 文本布局复制沿用换行连接和内联替代文本。被拖动选中的行使用原 BetterText pin 行为；极长拖选仍可能保留很多行，本阶段未承诺这一路径的内存上界。

“全选”通过选择组读取该 Text part 的完整原始源码，包含未挂载内容，释放全选产生的行 pin，滚动中新挂载文字按全选高亮。全选没有可拖动的首尾句柄；取消后可重新长按局部选区。全选复制保留 Markdown 源码和原始换行，普通局部选择复制的是显示文本，两者不是反向源码坐标映射。

动作栏与复制面板的复制按钮统一从最新完整 `UIMessage.toText()` 取值。复制面板只读预览按最多 4096 UTF-16 字符分片，避免劈开代理对，跨片连接不额外插入换行；全选/复制仍来自完整原文。编辑、发送、导出和持久化继续使用原始模型，不使用显示范围裁剪。

BetterText 的布局通知只在选中文本的实际位置、StaticLayout/PreparedText 身份或容器边界变化时更新，避免 toolbar/popup 自身重排再次触发布局状态的反馈循环。旧公开容器入口保持不变，新共享选择组和全文回调为附加 API。
