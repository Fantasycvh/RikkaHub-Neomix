# 长文 P4：流式增量显示

基于 P3 提交 `d5ac31b45`，将长消息后台准备扩展到生成阶段。标准布局的实色/隐藏气泡支持流式区块化；其他布局和复杂可见材质使用增量解析结果渲染完整消息，以保留外观，不声称这些布局已经区块懒加载。沿用“长消息按需显示”开关。

## 会话与刷新

每个节点维护独立 MessageDocumentSession 和按原始 part 下标隔离的 MarkdownStreamParser。会话仅由同一个后台 collector 串行访问；输入 snapshotFlow 使用 conflate，解析期间到达的中间快照合并，完成后处理最新输入，不对同一个 parser 并发调用或每个 token 取消重启。退出会话时取消 collector，离开当前窗口的节点释放解析会话。

追加文本保留 epoch 和前缀单元 id；既有安全分组从文首开始，新增尾部不移动前缀分组边界。相同输入复用整份文档，原始分支、配置、正文结构或非追加编辑变化重建会话。归一化和视觉正则仍作用于完整输入，解析器按其自身前缀规则失效；后置引用定义仍可要求全量转换，不能假定前缀语义永不改变。

后台处理追加时保留上一份显示文档，避免正文反复变成占位符。完整复制回调直接读取最新消息源码，和正在显示的上一份投影分离。生成中首次准备及结束前准备尚未完成时保留完整宿主；最终 streaming=false 使用同一个解析会话收尾，取消未闭合语法的流式补全。

已有区块的布局随离屏回收，解析前缀复用原节点实例；外观、引用定义和配置变化仍可能使前缀重绘，不承诺所有更新只触及最后一个区块。列表描述和完整源码/AST 仍保留，P4 并非数据层分页。进入区块的首次切换仍有 UI 创建成本。

## 阅读与贴底

完整消息行内部只有像素偏移，没有可逆的源码位置。如果用户正在该行中部阅读，延迟首次区块化，直到到达开头/底部；期间仍消费后台增量解析结果。已区块化的消息继续用稳定 key 和显示范围恢复位置。

引用/逻辑消息跳转、拖动解除贴底，明确到底部的命令恢复跟随。生成结束仍保留贴底意图，让最终语法、动作栏和尾部按钮完成布局；用户已离开底部时不恢复跟随。已在底部不重复请求布局。拆分消息的生成振动由稳定消息头统一观察，正文单元不独立振动。

## 边界

- 小于 8000 字符或少于四个可见安全单元时仍完整渲染；巨型单段、列表、围栏、表格保持整体，留到 P5。
- 工具/附件增删或思维链分组改变属于结构变化，保守重建，期间使用完整路径；不保证复杂工具结构切换具有追加纯正文一样的区块身份。
- 全选复制的是选择时的源码快照；继续生成不会悄悄扩展已有全选。动作栏复制使用当前完整消息。
- 字号变化和任意源码改写只尽力恢复区块与像素偏移，没有源码字符到屏幕位置的精确反向映射。
- 真实网络图片/公式、第三方布局的分段外观及 Release 性能尚需专项验证，不由离线回放替代。

构建、回归和性能证据见工作区 `app/build/p4-*.log` 与 `_measure/longtext/p4_*`；最终验收数字另行记录，不沿用 P3 性能数字作为 P4 收益。
