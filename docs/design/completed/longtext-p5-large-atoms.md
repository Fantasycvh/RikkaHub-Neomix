# 长文 P5：超大原子块与可选分段编辑

基于 `2457fb826`，保留 P4 之后的纹理/气泡层及 shader 改动。P5 测量普通安全分块无法拆开的巨型段落、围栏、列表、表格和 HTML 分组，不以字符切片重新解析 Markdown。原始消息、完整 AST、发送/导出/复制的数据来源不变。

## 超大块默认预览

沿用当前聊天列表允许分块的布局/材质策略。当单个安全单元的显示源码超过 24000 UTF-16 字符时，即使全文只有这一个单元，也可进入区块路径。该阈值是可调的工程保护值，本轮并未对阈值作全面扫参。

纯文本段落（单个 Paragraph，行内节点均为 Text）保持完整显示：先行实验没有证实其默认折叠的滚动收益，P95 有回退。复杂原子块在聊天中显示明确标注的折叠预览：直接读取该单元 parser-normalized 源码的前最多 3000 字符，避开代理对中间，最多显示 64 行；预览不经过 Markdown 重解析，不假装是完整富文本。入口位于预览顶部，避免必须滑过整个预览才能操作。

- “查看完整原文”复用已有懒加载只读复制面板，查看的是完整原始消息，包括其他文本 part，不是按显示坐标反向裁剪的原始块。
- “展开完整排版”由用户明确选择后，使用保留的原始节点渲染。它仍可能昂贵；本阶段没有让整张巨表的完整排版自动变成低成本操作。
- 已挂载的生成区块跨过阈值时保持展开，避免阅读中突然折叠；首次在大块状态下挂载则使用预览。开关“长消息按需显示”关闭后保留原路径。

这是一条有界的默认显示路径，不是对表格行/列表项的等价分页；截图/导出、不可分块布局、显式展开和完整解析仍可能有大块成本。完整 source/AST 仍在内存，不能把预览收益称为数据层分页或消息截断。

## 按测量选择分段编辑

当前版本 10 万字单段的全屏实际切换路径，三轮输入至绘制 P95 中位数为 127.05ms，仍明显高于交互帧预算，因此增加可选模式，不自动替换全文编辑。

全文编辑器达到 24000 UTF-16 字符时提供“分段编辑”。初始按最多 4096 字符生成草稿段，避开代理对；每次只挂载一个常驻 TextField，不放进 Lazy item。允许插入空白段，单段继续输入没有隐藏的硬长度上限，因此用户仍可自行把一段写得很长。

每个草稿段的 TextFieldState 是该段唯一编辑权威，切段显式结束旧焦点后使用另一段的状态；已访问段的文本、选区和局部撤销状态留在会话内。全屏的原 TextField 在分段模式中卸载，不会同时排版全文。

草稿会话存放在 ChatInputState，与原编辑状态具有相同的进程内生命周期，不写入 Android Bundle。当前段从全文原光标所在位置开始。切段不回填全文；“应用并返回”才在结束焦点后按原顺序合并，恢复全文光标。取消、返回关闭均保留原文。应用前比较完整原文和编辑目标身份，发生外部更新时拒绝覆盖；切换历史编辑目标也清除旧会话。附件与多文本 part 的合并仍走原 ChatInputState。

分段是一次独立草稿事务，不能跨段连续拖选；应用后的全文撤销历史不保证沿用旧历史，局部撤销限于草稿会话。原有全文模式保留原选择/撤销行为。进程被杀后的草稿恢复不在本阶段承诺范围；全屏输入宿主在进程内存活时保留会话。

## 验证口径

滚动对照使用当前 HEAD 重建的 before 与最终 after，10 万字 dense/code/list/table，各三轮。after 是默认折叠预览；必须同时报告表示方式变化，不能说完整十万字富文本的渲染耗时等价下降。P4 旧归档包的先行探索单独保留，不作为当前 HEAD 的 before。

编辑的 edit_handoff_full 保持既有协议；新增 edit_segmented 在实际分段 Dialog Window 中通过 InputConnection 测量当前段首/中/尾的提交与选区。行记录增加 active_editor_length_before 和 editor_page_count。它不测跨段跳转、全文合并或初始切换的端到端延迟，不能与全文首/中/尾的测量当成完全相同的编辑位置。性能样本、完整数据与限制见验收记录。
