## 1. 推荐方案

新增应用级 `ProviderModelCatalogRepository`，统一获取、缓存和发布各提供商的远端目录。设置总览、提供商模型页、可用模型面板、聊天模型选择器共用它。先交付 #2281，再利用相同快照交付 #2282。

目录刷新不改写 `ProviderSetting.models`。该字段继续保存用户已添加的模型及其稳定 UUID、别名、参数和启停设置；远端目录是独立的观测数据。models.dev 继续提供通用模型能力元数据，不参与判断某个账号是否列出某个模型。

缺失提示统一表达为「未在本次凭据对应的完整目录中找到」，不推断推理一定失败，不自动删除、停用、替换或取消收藏。手工添加的模型也遵循该规则。

## 2. 当前源码与必须先处理的问题

| 位置 | 当前行为 | 实施要求 |
|---|---|---|
| `SettingProviderDetailPage.kt` 的 `ModelList` | 局部 `fetchState`；`LaunchedEffect(providerSetting, refreshTrigger)` 直接调用 `listModels` | 移交共享仓库；编辑别名、添加模型、排序等不再触发网络请求；请求离开页面后仍可完成 |
| `Provider.kt` | `listModels` 只返回 `List<Model>` | 补成功、部分结果、失败、不支持以及结果完整性契约 |
| `OpenAIProvider.kt` | 缺 `data` 返回空列表，缺 ID 的项被跳过 | 区分合法空目录与异常结构；坏条目不能被静默跳过后仍声称目录完整 |
| `GoogleProvider.kt` | HTTP 失败返回空列表；只读一页；过滤非聊天/嵌入条目 | 失败显式返回；处理分页；保留用于存在性判断的原始 ID 集合 |
| `ClaudeProvider.kt` | 只读一页；缺 `data` 返回空列表；阻塞 `execute()` | 处理分页与严格校验，支持协程取消，关闭 response |
| `parseCodexModels` / `ChatGPTProvider` | 畸形响应可能变成空列表；可见性过滤后返回候选模型 | 区分解析失败；存在性集合保留原始条目，不受选择器可见性过滤影响 |
| `GrokProvider.kt` | CLI/API 两目录只成功一个也算返回成功 | 单源成功标为部分结果；不能据此判定缺失 |
| `KeyRoulette.default()` | 本仓当前取首个启用 key | 目录刷新沿用当前优先 key，但固定整次请求的凭据，不能分页中途换账号/key |
| `ModelListState.filteredProviders` | 已过滤停用/没有可选模型的提供商 | 面板级刷新从入口允许的 `state.providers` 再筛选资格，不能只刷新搜索结果或已有可选模型的分组 |
| `Model.providerOverwrite` / `findProvider` | 单模型可使用另一套实际请求配置 | 首版保守标为不可据所属目录比较，保持可用 |

分页依据：[Gemini models.list](https://ai.google.dev/api/models) 使用 `nextPageToken/pageToken`；[Claude Models API](https://platform.claude.com/docs/en/api/typescript/models/list) 使用游标分页。Vertex 与各兼容网关的分页格式须按其实际端点分别适配，不能直接套另一种协议。

## 3. 获取契约与数据分层

建议增加 `Provider<T>.fetchModelCatalog(setting)`，由五种 provider 实现。迁移期间保留原 `listModels` 为向新接口投影的兼容方法，禁止保留两套独立 HTTP 逻辑；UI 切换后再清理旧方法。

```kotlin
sealed interface CatalogFetchResult {
    data class Complete(val entries: List<CatalogEntry>, val scope: CatalogScope) : CatalogFetchResult
    data class Partial(val entries: List<CatalogEntry>, val scope: CatalogScope, val reason: IncompleteReason) : CatalogFetchResult
    data class Failed(val error: CatalogError) : CatalogFetchResult
    data class Unsupported(val reason: UnsupportedReason) : CatalogFetchResult
}
```

`CatalogEntry` 是远端 DTO，至少有实际 API ID、显示名、模型类型提示和是否作为添加候选项显示。它不持有本地 `Model.id`。选择添加时才生成持久 UUID，并沿用现有 `ModelRegistry` 能力补全流程。

必须同时保留：

- 原始目录中的 API ID 集合：供存在性检查使用，不受模型类型、可见性、搜索或本地启停筛选影响。
- 可用于添加的候选条目：可按协议支持范围、可见性和 UI 搜索筛选。
- 端点/凭据范围、完整性、获取完成时间；不把网关目录扩展解释成所有下游账号的权限清单。

只有适配器可以认定 `Complete`。所有必要数据源成功、分页结束、结构可识别且未遇到无法确定 ID 的坏条目时才成立。明确返回合法空数组可以是完整空目录；缺失字段、HTML、错误对象或错误被转换成空列表均不成立。协议允许省略空集合的情况需单独明确并测试，不能通用 `?: emptyList()`。

分页必须固定凭据；任意中途错误、重复游标、达到保护上限均不得发布完整结果。建议保护上限为 100 页或 20,000 条，触顶显示不完整，不据此比较缺失。去重使用精确 API ID，保留原始大小写；Google 资源名到调用 ID 的映射由适配器统一处理，不做通用小写化、去来源前缀或模糊相等。

失败分类包括：连接/超时、明确鉴权失败、限流、服务端错误、解析错误；保留 HTTP 状态与有长度限制的脱敏摘要。404/405 显示「目录端点未找到或不支持」，不永久推断整个提供商不可用。`CancellationException` 原样上抛。

## 4. 按配置和凭据隔离

目录键使用 `providerId + scopeFingerprint`。相同名称、URL 的两个配置仍完全独立，不能共享请求结果或缺失结论。

指纹只覆盖影响目录请求的字段：provider 类型、实际目录端点、有效自定义头、当前选中 key、代理与继承的全局代理修订，以及 Google Vertex/service-account 的项目、区域和认证模式等。provider 名称、已添加模型、模型别名、排序、推理参数和收藏不进入指纹。

指纹使用规范化字段的带本机随机盐摘要，落盘不保存密钥、Authorization、私钥或 token 的副本。变更地址、凭据、头或实际请求范围后，立即把旧判断变成未知；返回中的旧请求须通过范围和 requestId 双重核对，禁止覆盖新配置。

### 多 key

首版每次刷新只使用当前优先启用 key，整次分页固定同一把，不扫描所有 key、不对各 key 的目录取并集。详情明确显示「基于当前优先 key 的目录」，缺失文案限定为本次凭据范围，不声称其他 key 也缺少该模型。无 key 但服务允许免鉴权时可以尝试目录获取。

切换优先 key、禁用/改写当前 key 会使结果失效。未使用 key 的变化不必失效当前结果；key 列表本身仍由现有配置负责，不增加轮询路由系统。

### OAuth 账号

账号范围需要稳定的登录会话标识：登录、退出和导入/替换账号时换代，正常 access/refresh token 轮换保留该代。建议为账号凭据增加可选 `loginSessionId`，在 `ProviderAccountManager.persistCredential` 的新登录路径生成，`replaceCredential` 自动刷新路径保留；旧数据在首次使用时补齐并持久化，导入路径重建本地会话代或清除相关目录快照。

不能只按 email 或 nullable `accountId` 判断同账号，也不能每次 access token 更新都换目录范围。获取期间发生同会话正常续期可以继续；退出、切号或更换配置则丢弃旧结果。该账号生命周期钩子应随共享仓库一起实施并有并发测试。

## 5. 共享状态、持久化和调度

仓库由 Koin 注册为单例，使用进程级受监督 scope 和 IO dispatcher。UI 只订阅状态与发出刷新动作。

每个提供商的状态拆成两部分，避免单个 `UiState<List<Model>>` 丢掉历史：

- `lastComplete`：最近一次完整目录及其完成时间和范围。
- `lastAttempt`：最新请求 ID、触发来源、排队/刷新/完成状态、时间、部分结果或失败原因。

完整成功原子替换 `lastComplete`；部分结果和失败仅更新本次尝试，不清空旧完整目录。UI 可继续显示旧候选，但明确标「上次成功结果」及时间。部分结果可以单独用于候选浏览，不能伪装成本次完整成功。

使用 app 私有 `noBackupFilesDir/model-catalog/` 持久化有版本的每配置快照与用户确认记录，不把远端目录塞进 Settings、Room 聊天表或跨设备同步；核对手工备份路径也显式排除此目录。临时文件写完原子替换；启动先加载本地再按策略请求。坏缓存回到未知，配置删除清理快照，配置范围变化清除旧判定；不持久化运行中的 Job，重启后未完成请求标为中断。

| 策略 | 建议首版默认 |
|---|---|
| 页面按需自动刷新 | 全局开关默认关闭，用户可开启 |
| 目录有效期 | 6 小时，先作为内部常量；不增加多项高级设置 |
| 手动刷新 | 忽略 TTL，空闲时实际发请求；已有同范围请求进行中时共享该请求并展示进度，不用缓存冒充刷新 |
| 自动刷新去重 | 页面进入时检查范围和有效期；搜索、重组、排序不触发；失败后至少间隔 60 秒再自动尝试 |
| 批量并发 | 全仓库共享上限 3，同一配置同时最多一个刷新；一个失败不取消其他配置 |
| 超时 | 整次目录刷新 30 秒，超时可保留部分结果但不发布完整结果；后续可按实际长目录调优 |

批量刷新点击时固定目标配置 ID，不受搜索/折叠变化影响；排队到执行前重读范围，已删除/停用的批量目标跳过并在汇总解释。未登录的账号配置显示「需登录」，不发鉴权必败的请求；API Key 类不能仅因 key 为空就排除免鉴权本地服务。单条显式刷新可以检查停用配置，但不改变其启用开关。页面离开不取消共享请求；配置失效或删除取消对应请求。注册锁仅用于状态变更，不能持锁等待网络。

手动刷新显式绕过客户端 HTTP 缓存，首版直接发网络请求，不实现条件重验证；后续如接 ETag/304，必须有同一范围的旧完整快照才能据 304 更新时间，不能把没有快照的 304 当作空目录。

TTL 过期不删除历史证据，只改变为「上次检查」；从其他入口完成刷新后，当前页面立即接收相同状态。进程启动只加载缓存，不主动全量访问所有提供商。

## 6. 缺失判断与提醒

计算对象是提供商当前所有已添加模型，包含手工添加及已停用项；比较实际 `modelId`，展示用户别名和 ID。UI 选择器仍保留既有启停/类型过滤，不因目录缺失额外隐藏模型。

| 证据 | 展示与判断 |
|---|---|
| 当前范围的完整目录包含该 ID | 已列出，清除缺失标记 |
| 当前范围的完整目录不包含该 ID | 未在该完整目录找到，记录检查时间 |
| 本次失败/部分结果，存在同范围旧完整目录 | 本次检查未完成，旧结论注明「上次完整检查」时间；不增加新缺失项 |
| 没有完整目录，或范围已改变 | 尚未检查/结果未知，不标为缺失 |
| `providerOverwrite != null`、模型级请求头或 `model` 请求体覆盖 | 首版显示「使用独立模型配置，未按此目录检查」，不据所属目录判定缺失；后续再考虑独立范围获取 |

缺失集合从当前本地模型列表与快照派生，不把模型 UUID 列表当永久真相存入 Settings。改别名立即更新展示；改 API ID、删除模型或改覆盖配置立即重算，不需要发目录请求。最近一次完整目录之后添加的模型只可表述为「未在上次完整目录中找到」，不能声称它已经下架。

完整刷新结束后若有缺失，显示提供商级常驻摘要「N 个已添加模型未在本次目录中找到」，可进入包含具体名字、ID、时间和范围说明的详情。首版采用页内状态，不依赖转瞬即逝的 toast，不发系统通知或连续弹窗。

「知道了」只收起同一缺失事件的摘要，行内标记和详情继续可查；不改成已列出。确认记录按配置范围、本地模型 UUID、API ID 和缺失事件保存。连续刷新仍缺失不反复打扰；完整目录重新包含后结束该事件，以后再次缺失可以重新提醒。

## 7. 四个入口的交互

| 入口 | 刷新范围与反馈 |
|---|---|
| 设置 → 提供商总览 | 明确的「刷新全部模型列表」，范围为全部启用且支持获取的配置，不随搜索缩小；行内可单独刷新。逐项展示成功数量/时间、失败或不支持，并提供批次汇总 |
| 单提供商模型页 | 显式刷新按钮与共享状态条；失败时可以原地重试；已添加模型始终可见，缺失项附标记 |
| 可用模型面板 | 同一提供商目录的候选视图，增加原地刷新与时间/旧数据说明，直接订阅共享状态 |
| 聊天模型选择面板 | 顶部刷新全部符合条件的提供商，每个分组可单刷；搜索不改范围。订阅会话锁定时仅刷新入口允许的提供商；使用 `state.providers`，不使用已筛掉空分组的 `filteredProviders` |

聊天中当前模型缺失时，在模型入口附近显示小型警示，可点开详情/刷新，不打断输入、不阻止选择和发送。收藏区与普通分组都消费同一标记。禁用模型本来不在选择器展示，仍可在提供商管理页查看其检查结果。

状态条和缺失标记不改变列表 key：提供商用持久 provider UUID，已添加模型用本地 UUID，候选项用提供商范围内的实际 API ID。刷新不得重建正在编辑的模型表单；说明详情用 sheet 的常驻滚动 Column，`supportingContent` 多块内容用 Column 包裹。实现资源变更时使用 locale-tui 覆盖英文、简中、繁中。

## 9. 实施记录

### A：可靠目录契约（2026-11-03）

- 新增 `ModelCatalog.kt` 的类型、严格解析、分页收集、HTTP 分类与取消传播；五个提供商实现 `fetchModelCatalog`，旧 `listModels` 仅投影添加候选。
- Google/Claude 补分页；Vertex 使用原始资源 ID，能力未知的条目不强行作为聊天候选；ChatGPT/Grok 保留隐藏/非聊天 ID。Grok 两个必要源均完整成功才发布完整目录，单次刷新固定一份账号凭据。
- 兼容网关出现无法识别的分页信号时保守标为部分结果；错误对象、缺集合、缺 ID 均不能成为完整空目录；合法空数组仍是完整结果。
- 新增 `ModelCatalogTest` 14 项：MockWebServer 实际请求、分页凭据/参数、HTTP 分类、缺字段/坏条目、未知分页、游标循环、保护上限、取消、超时、双源合并与隐藏 ID。
- `:ai:testDebugUnitTest` 全量 **505 项，失败 0、错误 0、跳过 0**；`:app:compileDebugKotlin` 通过。构建沿用本机 JetBrains JDK 21、既有 Gradle 缓存及临时官方 HugeIcons 本地镜像 init script（仓库依赖声明未改）。
- 分页核对来源：上文 Google/Claude 官方文档，以及 [OpenAI Models API](https://developers.openai.com/api/reference/resources/models/methods/list)。

### B：共享仓库与凭据范围（2026-11-03）
