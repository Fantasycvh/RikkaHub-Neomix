# 助手级双记忆模式

> 2026-11-12 · 设计草案。已确定的产品语义为按助手选择模式、旧助手默认条目记忆、两套数据分别保存且切回可继续使用。下文的交互、存储和分期为设计提议。

## 1. 用户看到的行为

在助手详情的「记忆」页增加「记忆模式」选择。页面先显示当前模式，再展示对应的内容管理区。

| 模式 | 聊天中的行为 | 管理页 |
| --- | --- | --- |
| 条目记忆（GPT 式） | 使用现有的画像、话题、事务，以及分层注入、相关性检索和按需读取 | 现有条目列表、筛选、排序、历史、回收站和整理入口 |
| 文件记忆（Claude 式） | 将画像、偏好放在固定 Markdown 文件里。模型看到文件目录后可按需读取和编辑话题、项目或人物文件 | 按路径浏览、新建、查看、编辑和删除 Markdown 文件 |

- 已有助手和缺少该设置的旧备份默认使用条目记忆。新助手也以条目记忆为默认值。
- 模式随助手保存。一个助手的已有会话在下一轮发送、重新生成或从历史分支生成时采用该助手当前所选模式。聊天模型可独立更换。
- 「启用记忆」控制该助手的记忆能力。「不使用记忆」继续对当前会话生效。模式值在关闭记忆期间仍会保存。
- 「全局记忆」继续决定使用私有库或全局库。全局条目库和全局文件库各自独立。两个助手只有在选择相同模式且都开启全局记忆时才共享相应内容。
- 切换只保存模式设置。首次进入空库时展示该库的空状态。切回原模式后恢复访问原库内容，包括切换前已保存的条目或文件。若旧轮次仍在执行或其他助手共享该库，切回时可看到它们后来提交的写入。
- 建议在选择器下显示「切换后，新回复将使用所选模式。两套记忆会分别保留。」模式切换使用普通设置交互。若当前文件有未保存编辑，先处理保存或放弃，再切换页面。

例如，助手 A 在私有条目库中保存了「默认用中文回答」。切到私有文件库后，首轮只使用文件库中的内容。即便模型随后创建了 `/preferences.md`，切回条目模式仍可看到原条目，下一次切回文件模式也能看到该文件。另一个助手的私有库独立于这两套数据。

## 2. 设置与存储

在 [`Assistant`](../../../app/src/main/java/app/androidrik/rikkahub/data/model/Assistant.kt) 增加可序列化的 `memoryMode`，建议稳定存储值为 `entries` 和 `files`。缺省值为 `entries`。兼容解码应识别缺省字段，遇到未知值时回退为条目模式并记录兼容提示，避免整份助手配置解析失败。

运行时的记忆库身份由 **模式和库 ID** 共同决定。库 ID 沿用当前私有助手 ID 与全局库 ID 的取值。条目模式沿用 `MemoryEntity` 及现有的历史、提案和回收站。文件模式在同一个 Room 数据库新增文件表，使用 `(库 ID, 规范化路径)` 作为联合主键，存储 Markdown 正文、更新时间和写入版本。空库由零行表示。

文件路径是库内的逻辑键。复用本地 `upstream/master`（核对到 `90269e39d`）的路径规则、文件模型、目录约定和编辑交互。固定路径为 `/profile.md` 和 `/preferences.md`，常用目录为 `/topics/`、`/areas/`、`/people/`。UI、模型工具和导入共用同一套路径校验。编辑和删除携带读取时的版本，写入时在事务内比对；删除后重建同名文件须分配新版本，过期操作返回冲突。

切换本身没有数据库写入。升级迁移仅新增文件表，已有条目及其 ID、版本、排序、历史和待审整理提案沿用原存储。删除助手时，按现有私有数据清理入口处理该助手的两种私有库。全局库由自身的管理操作清理。

## 3. 聊天、工具和切换边界

每轮生成开始时，根据助手设置和会话记忆开关解析一次记忆模式及目标库。加载记忆、提示词装配、工具注册和执行、提示词预览共用同一解析规则。一次生成的后续工具轮沿用启动时的目标。关闭记忆时，跳过库加载、记忆注入和记忆工具注册。

| 环节 | 条目模式 | 文件模式 |
| --- | --- | --- |
| 请求装配 | 复用现有 `MemoryInjectionPlan`、锚点和尾部注入 | 默认注入画像和偏好文件正文，其余提供路径和描述。正文、目录及工具返回均受预算约束。超出预算的内容通过工具按需读取 |
| 工具 | 复用 `memory_tool` 及其原有参数和审批策略 | 复用上游读、列目录、写、替换、追加、删除的语义，通过现有跨 Provider 自定义工具通道注册 |
| UI 和预览 | 显示原有记忆段、锚点和条目操作 | 显示文件记忆段、已注入的文件及目录，工具卡片显示逻辑路径和操作 |

文件工具的读取、列目录直接执行。新建受现有「记忆创建审批」开关控制，覆盖、追加、替换、删除受「记忆修改审批」开关控制。`write` 根据目标是否存在区分新建与覆盖，并在真正执行时校验相应的存在条件或版本。首版的「Claude 式」指 RikkaHub 原版的文件模式，使用应用自己的跨模型工具协议。

**切换发生在下一轮生成。** 例如，条目模式的一次写入等待审批时，用户可以切到文件模式。审批卡仍显示原来的模式和私有／全局库，批准只对原库和原版本生效。运行恢复需要读取持久化的目标，不能从助手当前设置反推。存量待审批若缺少可验证的目标，则提示用户重新发起操作。失败、重试和重复批准都要沿用同一目标并避免重复写入。

旧会话继续展示完整历史。请求装配时，只重放与本轮目标库匹配的记忆工具调用与结果，成对处理调用及返回；普通聊天正文仍按既有上下文规则发送。因此之前已经写进聊天正文的信息仍可随聊天上下文进入模型。旧条目会话在可确定库身份的情况下兼容旧工具历史。回到条目模式时复用该会话针对相应条目库保存的锚点状态。

现有 [定时任务审批桥](../../../app/src/main/java/app/androidrik/rikkahub/data/task/ScheduledMemoryApprovalBridge.kt) 按 `memory_tool` 名字识别待审批调用。文件模式开放给定时任务前，审批桥、工具效果分类和记忆写入回执都要能识别文件操作。缺少可用审批通道时，沿用定时任务现行的拒绝处理。

## 4. 整理和备份

**文件分类。** 文件页从路径推导分类。`/profile.md` 为画像，`/preferences.md` 为偏好，`/topics/`、`/areas/`、`/people/` 分别为话题、项目、人物，其余归入「其他」。编辑时可通过改路径移动文件。源文件版本和目标路径在同一事务中校验。

**整理。** 两种模式共用手动、自动和定时触发机制。文件模式的自动开关、会话水位、复核游标和建议按文件库保存。轮次按生成时的模式和库归属取用，旧轮次按条目语义兼容。文件整理支持新建、编辑和移动。编辑建议要求整理器已读取完整版本，移动建议保留源正文，画像和偏好固定路径可由用户手动调整。审批开启时，建议持久化后由用户逐项查看和决定，采纳时复核源版本及目标路径。关闭相关审批时，整理结果和水位同事务提交。手动复核按路径分页，自动整理聚焦新轮次。

**备份。** 设置备份携带模式选择。含数据库的完整和增量备份均应保存两个库的数据，包括当前未选中的库。备份恢复用例要覆盖「当前为文件模式，恢复后切回条目」和相反方向。只恢复设置时，内容取决于设备现有数据库。旧 Neomix 含数据库备份按现有恢复策略导入条目库，新表随迁移建立。原版备份继续沿用现有 [Markdown 转条目](../../../app/src/main/java/app/androidrik/rikkahub/data/sync/LegacyBackupConverter.kt) 路径。原版文件原样导入和两种模式间的显式复制另立需求，切换模式本身没有转换步骤。

## 5. 实施分期与验收

1. **存储与界面。** 接入设置兼容、Room 迁移和文件管理页。验证 A/B 助手独立选择，私有库隔离，同模式全局共享，以及反复切换和重启后两套内容均可恢复访问。
2. **请求与工具。** 接入聊天、提示词预览和定时任务。验证已有会话跨模式续聊、隐身会话、缺少工具能力的模型、审批后恢复、同名文件并发更新、切换时在途写入和历史工具结果的隔离。
3. **后台与恢复。** 验证条目整理在切走及切回时的轮次归属，覆盖全局库参与助手混用两种模式的情况。用完整备份和增量备份分别进行恢复往返，再切换两次核对内容。补测旧版本升级、旧备份和删除助手。
