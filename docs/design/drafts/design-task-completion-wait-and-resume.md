# 任务完成后自动恢复对话

日期：2026-11-08。本地实施草稿。

## 行为

开启设置中的“后台任务完成后自动处理”后，对话中的子代理统一以后台方式派发，立即返回 run ID。模型可以继续独立工作，然后调用 `await_background_tasks` 正常结束本轮。后台命令也遵循同一提示和等待协议；无需用户发送新消息来释放会话。

完成事件写入收件箱，等会话空闲后作为有来源的运行时数据送给模型，再继续原任务。新用户消息优先处理；旧 root 的结果不会注入新问题的步骤，等新问题结束后再处理。

原设置字段 `workspaceTaskNoticeEnabled` 保留兼容，界面名称覆盖子代理和后台命令。补齐此前缺失的 DataStore key、读取与写入。默认仍关闭；不修改用户已有配置。关闭时保留原预设执行方式及旧后台子代理开关的语义。定时任务和无头 run 保持原行为；普通前台工具不转移到后台。

## 等待与生成循环

`await_background_tasks` 只在支持自动续跑的普通聊天中装配，不授予子代理或定时任务。它从当前选中分支的真实工具回执、运行账本和命令快照中识别本 root 的未完成任务，不接受模型自报的任务身份。

成功等待后，通过受信任工具定义的 `endTurnOnSuccess` 结束当前生成。整批工具结果先完整回填，待审批工具仍走原审批路径；不通过取消 Job 来结束等待，因此不会触发后台任务取消清理。任务若已在检查前完成，工具返回正常 `ready`，继续消费结果，不制造错误或空等。

工具说明在启用自动续跑时明确要求：先派发独立任务、处理独立工作，再等待；不反复轮询、不 sleep、不重新派发已接受任务。关闭自动续跑时仍可按原方式查询命令状态。

## 共用持久化收件箱

Room 升到 63，`SCHEMA_VERSION` 与导出 schema 同步：

- `agent_run.notice_target` 保存派发前捕获的 conversation、assistant、workspace、用户锚点、root 与唤醒权限。没有绑定 workspace 时存空字符串；工作区变更仍参与路由校验。
- `external_notice.sourceType` 默认 `workspace`，新子代理事件使用 `subagent`。旧记录升级不会自动获得新唤醒权限。
- 自动续跑子代理使用 `delivery_mode=resume`，终态与 pending 标记原子提交。它们不进入旧的只投递通知泵，避免双投。
- 完成事件先幂等进入收件箱；会话消息、收件箱投递确认、agent 投递确认在同一 Room 事务提交。进度更新不能覆盖投递元数据或已落终态。

命令和子代理都验证当前选中分支的原始回执与用户锚点。一轮生成只唤醒一个原始 root；多个 root 的结果不会在首次续跑时混在一起。任务中心和原审批入口继续有效。

## 取消、让路和恢复边界

停止或手动“保留任务并立即发送”会写入 `cancel_scope` 控制记录，阻止该 root 尚未产生的完成事件在应用重启后重新唤醒。控制记录不作为消息投递，随已解决收件箱记录按 30 天清理。

手动让路仍保留已启动任务。原来使用统一收件箱的 resume run 不切回旧通知泵；只抑制唤醒，避免两条投递路径重复显示结果。启动已完成但工具回执尚未回填的子代理，在让路收尾时按实际运行账本补回 run ID。

原始 root 最多自动消费 8 个完成事件作为续跑触发；各事件最多 claim 一次。到上限后结果仍可见，等待工具要求明确继续，不再承诺自动恢复。启动时将中断的 claimed/started 续跑记为失败，不重放可能产生副作用的生成。

进程死亡不恢复已经丢失的执行：子代理沿用 interrupted 对账；后台 shell 沿用既有进程和日志回收边界。该实现提供持久化结果与唤醒状态，不承诺跨进程恢复任意任务。
