# 整套 AppSkin 试穿、撤销与版本回滚

## 用户流程

- 应用皮肤的方案选择器现在只选择候选；点击“试穿整套皮肤”临时预览，或点击“直接应用方案（保留覆写）”沿用直接应用方式。
- 全局编辑器新增“跨页面试穿”，关闭编辑 sheet 后可以在聊天、设置、抽屉等页面查看结果。
- 皮肤资源包中每个方案提供“试穿整套”和“历史版本 / 回滚”。
- 试穿时显示固定默认样式的救援条，提供“撤销”和“确认应用”。两分钟未确认自动恢复。
- 确认后提供一次“撤销”，恢复此前的皮肤选择与覆写；点击“完成”收起这个撤销机会。

范围是全局 AppSkin 契约：字体、形状、间距、动效、可选配色、面板、嵌入式渲染器与图片。
独立的聊天专属外观、既有主题角色颜色覆写及其他偏好不在本轮试穿事务中，也不会被写回覆盖。
方案试穿暂不使用 AppSkin 用户覆写，确认后保存该方案选择和空覆写，继续跟随其更新。
编辑器草稿试穿则保存为独立全局样式快照（默认选择 + 全组覆写）。

## 临时状态与并发保护

SkinTrialController 只在进程内保存试穿与一步撤销记录，试穿本身不写 DataStore。
rememberAppSkin 对最终解析结果施加冻结的 AppSkin 试穿快照，纯 resolveAppSkin 保持无副作用。
根主题宿主负责展示救援条；嵌套主题不重复展示。宿主不强制扩大浮窗的默认布局尺寸。
关闭最后一个宿主会取消未确认试穿；多宿主使用独立租约，旧租约重复关闭不影响新试穿。
多窗口/宿主切换共享原始开始时间，不能重置两分钟期限。进程死亡后试穿自然消失，
已确认设置保留；一步撤销记录不跨进程重启持久化。

确认和撤销通过最新 SettingsStore.update(transform) 提交，只修改 appSkinId/appSkinOverrides。
界面确认绑定所显示的试穿令牌，撤销绑定所显示的撤销记录，延迟或排队的旧点击不能作用于新试穿。
确认前比较原皮肤字段，并验证目标仍存在且内容与试穿快照一致；撤销前比较确认后的字段
与方案内容。后续皮肤编辑、卸载或内容更新引起冲突时拒绝覆盖，保留现状并显示原因。
无关设置修改继续保留。确认写入和内存记账构成不可中途取消的短事务；写入失败可重试，
若写入期间宿主关闭，操作结束后也会清除未确认试穿，避免遗留无宿主的预览。

取消试穿恢复的是当前持久化外观，绝不回写旧的整个 DisplaySetting。
撤销不删除试穿期间创建的聊天、画纸或文件，也不撤销独立的资源包升级/回滚操作。

## 版本历史

活动目录仍是原来的 index.json 列表，无须迁移旧目录。升级前将已经提交的当前版本
原子保存为 history-<id>-<version>.json；当前版本始终从活动目录读出。
保留最高的 8 个版本号以及切换前后版本，最多 10 个可见版本；剪枝在新目录提交后执行。
共享字体/图片沿用已有哈希存储，不复制整份 ZIP，不回收仍可能被覆写引用的资源。
历史 JSON 使用同一受保护、参与完整备份的平铺目录；恢复后重启可继续读取。

切换版本需要明确确认，并携带界面看到的当前版本号，防止过期操作覆盖新版本。
目标清单、哈希、图片解码和字体再次验证后才原子切换目录并发布 Registry。
缺资源、坏资源或过期当前版本都不改变活动版本。回滚不通过 ZIP 重编码/解码转一圈，
避免额外的整包内存副本。相同版本内容不可替换；回滚后普通升级仍须高于所保留历史的
最高版本，避免复用已发布版本号。历史中也可再次切回较高版本。

用户覆写仍优先，可能遮住包版本的视觉差异；回滚不会清空这些覆写。
版本历史属于本机资源包，不随单个包 ZIP 导出，也不等同于整个应用设置历史。
卸载仍保留共享资源和已有历史；资源回收与总磁盘配额继续留待后续。
