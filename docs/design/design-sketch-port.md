# 画板移植

## 范围

参考本地上游同步镜像 `rikkahub-sillytavern-android`（核对时 HEAD `a9b95d45c`），
把 `ui/sketch` 的 Compose 画板移植到应用内 `ui/components/sketch`，避免为单一组件引入整个上游 UI 模块。

- 画笔、橡皮、文字、选框、移动与缩放；
- 预设色、自定义颜色、粗细选择；
- 撤销、重做、清空与退出丢弃确认；
- 空白画纸比例选择、相册底图、EXIF 方向修正及大图采样；
- 同一套绘制逻辑用于屏幕和导出，选择框不写入图片；
- 橡皮只清除笔画层，保留白纸和底图。

## 接入约定

- 媒体创作的素材选择器提供画板入口；导出进入当前素材角色（参考图或首/尾帧），复用会话内文件持久化。
- 聊天附件支持创建草图，以及在输入区已有图片上标注；结果另存为新文件，仅替换输入区引用，不覆盖原图。
- 图片光栅化在 Default 线程、保存与编码在 IO 线程执行；保存失败应显示错误，而不是添加损坏附件。
- 底图加载完成前禁止绘制与确认；加载失败保持阻止确认但可重选或关闭。导出中冻结输入、禁止退出并防重复提交。
- 媒体素材替换前将原图归档到 `media_creation/<session>/originals/<来源目录>/<文件名>`，避免下次清理无引用草稿时丢失原图；用同目录 `.part` 临时文件、长度校验、rename 转正，失败不替换引用。归档随会话递归备份与删除。
- 空白草图导出 PNG（长边 1536 像素），照片标注导出 JPEG（跟随采样后底图尺寸，长边不超过 2048 像素）。
- 使用 AndroidX Ink `1.1.0-alpha09`（与参考实现一致）及 ExifInterface `1.4.2`。

## 验证

- 调试应用与 Android 测试包构建通过；合入素材上传与安全日志后，app JVM 212 suites / 1944 tests、mediagen 33 tests、common 50 tests，均无失败。
- 设备状态/导出/归档测试：比例、撤销重做、文字选择变换、PNG/JPEG 格式及尺寸、橡皮保留底图、EXIF 摆正、降采样、编码失败、原图归档与失败清理。
- Compose 真机 UI 覆盖 Ink 画线→撤销→重做→确认导出，以及坏底图禁止确认；使用 debug-only 宿主及显式目标包 Intent，避免测试 Activity 被误解析到 `.test` 包；焦点/息屏与异步重组等待修正后，新增真实持久化测试后最终全批次 **22/22 通过**（状态 7、导出 5、UI 2、原图归档 5、聊天持久化 3）。UI 工具栏点击改为语义 OnClick，避免把窗口触摸注入失败误判为撤销/清空失败；相同代码随后两次 UI 类复跑各 2/2。坏图用例故意弹“无法加载图片”，不是保存失败；保留提示和应用内安全阶段日志。
- 手动真机：媒体画板画线→确认→PNG 落盘（21,018 bytes）→首帧素材显示；已有图片的“在图片上绘制”菜单可达。未调用收费生成接口。
- `lintDebug` 已运行但整仓不通过：现有本地 properties 转义、旧页面的 Compose 资源/Locale 读取及缺失翻译等错误。本次新增两处资源读取错误已修正；复跑报告未再列出画板及聊天接入文件。没有为通过检查而关闭 Lint。

## 边界

- 画板本地保存无需公网 S3。用户后续授权的独立素材上传接线见 [媒体素材远端存储](design-media-upload.md)；本轮未做真实云上传，也未主动调用收费生成接口。
- 画板是一次性的图片编辑窗口，不保存可重新编辑的矢量工程或草稿笔画。
- 设备旋转/进程重建后的笔画恢复遵循当前实现能力，不应作为持久化工程使用。
