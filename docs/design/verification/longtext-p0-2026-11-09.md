# 长文 P0 真机基线

2026-11-08 开始，2026-11-09 完成。业务代码基点 `3d8db3c64`，本阶段只增加采样设施及可选构建配置。

## 交付与执行

- 固定样本：普通分段、无换行长段、Markdown 混排，各 1 万 / 5 万 / 10 万字符。生成器另提供代码块、列表、表格压力样本。
- 生产组件：`ChatList`、`ChatInput`、`FullScreenEditor`；真实帧时钟，标准布局、默认字号、无玻璃效果，生成高度动画开启。
- 设备 PJX110 / Android 15。被测窗口请求且实际观测为约 60Hz。
- 完整矩阵：9 份样本 × 4 场景 × 3 轮 = **108 次测量**，9 个新测试进程全部正常结束。
- 最后一份混排样本有 3 组出现中度温控标记，保留原数据；其后分别独立复测流式、普通输入、全屏输入，各 3 轮，**9 次定点复测全部通过且无中度温控标记**。
- 合计 117 次测量，形成 36 组可用对照。来源明确区分：33 组取完整矩阵，3 组取独立复测；没有混合不同来源的帧，也没有按耗时优劣挑选单轮数据。
- 所有可用组均有有效帧与 deadline，帧回调丢失为 0。编辑每轮提交 18 个字符并断言长度和选区；流式每轮 40 次更新并断言最终文本完整。
- 6 项主机统计/完整性检查通过；IME 审计 A=0、A'=0，B=4/C=32 为现有警告。

原始数据、每个 cohort 的参数、设备/温度记录、日志、源码快照在 `_measure/longtext/`。应用和测试 APK 保存在主矩阵目录的 `apks/`；测试 APK SHA-256 已与设备实际安装文件核对一致。完整哈希和各组数据在同目录的 [机器可读汇总](longtext-p0-2026-11-09.summary.json)。

## 核心结果

下表为普通分段样本，单位 ms。先计算每轮 P95，再取三轮中位数。

| 字符数 | 普通输入：提交→下一次绘制 P95 | 全屏输入：提交→下一次绘制 P95 | 流式场景：帧耗时 P95 |
|---:|---:|---:|---:|
| 10,000 | 67.35 | 38.21 | 26.88 |
| 50,000 | 152.74 | 112.43 | 46.63 |
| 100,000 | 244.52 | 200.67 | 70.99 |

10 万字混排的独立复测：

| 场景 | 帧耗时 P95 | 提交→下一次绘制 P95 |
|---|---:|---:|
| 流式回放＋滚动 | 271.43 | 不适用 |
| 普通输入 | 373.32 | 392.96 |
| 全屏输入 | 360.14 | 378.17 |

这些数据确认了长文本输入和复杂 Markdown 流式显示的明显成本。它们是 Debug 组件基线，不是正式版 FPS、真实网络端到端结果或中文输入法组合输入延迟。工作区补全未启用，其优化需要另加场景。

## 已排除的测量设施问题

1. 该设备对新安装隔离包存在 instrumentation 可见性问题。采用正常 Debug 包入口和专用隔离 Application/内存库/临时设置，不加载用户会话与账号。
2. 早期 schema=1 驱动接入无障碍节点树，在无障碍事件发送链路出现带 `DeadSystemRuntimeException` 的 JNI Abort；按样本重开进程仍会遇到同类问题。旧数据只保留为诊断证据，不据此认定正常使用的应用必然崩溃。
3. 最终 schema=2 使用 `input_connection_no_accessibility_v1`：无障碍子系统不参与驱动，触摸直接注入，编辑/选区使用 InputConnection。9 个完整矩阵进程和 3 个补充进程均正常结束。

详细指标定义、隔离方式和 CLI 参数见 [运行说明](../completed/longtext-p0-baseline.md)。下一步 P1 可用这些来源明确的编辑基线做对照；本阶段没有实现长文懒加载或编辑优化。
