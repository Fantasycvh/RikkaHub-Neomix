# 长文 P1：编辑与补全优化验收

本阶段实现编辑链路优化，不包含长消息内部懒加载。基于 `5d9cb28d7`，保留原有 Material 输入框外观。

## 改动

- 底部输入和全屏编辑共用一个 `TextFieldState`，同一时刻只挂载一个 TextField；全屏时底部用等高占位，避免两个输入框同时响应长文变化并进行文本布局。两侧 ScrollState 保留，切换时恢复焦点，不重填全文；选区和撤销记录随共享状态保留。
- 补全上下文只复制光标之前最多 1,025 个 UTF-16 单元（1,024 上限及前置边界保护），不再每次把完整编辑缓冲区转为 String。局部范围映射回文档绝对位置，处理选区、邮件地址、截断 token、中文路径和代理对边界。超出窗口的超长 mention 不提供候选。
- 补全计算移到 `Dispatchers.Default`，继续取消过期请求；失焦/全屏时停止底部补全，点击候选前再次核对上下文，避免旧结果改错位置。
- 相同文本的程序化回填跳过缓冲区更新，保留选区；追加内容使用编辑缓冲区操作，去掉全文转字符串再拼接。切换编辑目标时清空撤销历史，避免相同正文的不同消息串用 undo。

## 真机对照

设备 PJX110 / Android 15；共享 Debug 包、隔离 Application/临时设置/内存数据库，不读取个人会话、不调用模型接口。prose 1 万、5 万、10 万字，每份样本独立进程、各 3 次；默认字号、无玻璃、无工作区补全、请求 60Hz。协议继续使用 `input_connection_no_accessibility_v1`。

新增 `edit_handoff_full` 实际路径：生产 ChatInput → 聚焦 → 展开全屏 → 实际 Dialog Window 中输入。切换及初始稳定等待不计入稳态指标，输入点依次位于文首/文中/文末。P0 的 `edit_full` 单独挂载编辑器，不包含背后的底部输入宿主，因此不能拿两个场景直接计算改造收益。

| 字数 | 输入至绘制 P95：改造前 → 后 | 降幅 | 帧耗时 P95：前 → 后 |
|---:|---:|---:|---:|
| 10,000 | 72.41 → 44.12 ms | 39.1% | 52.73 → 35.91 ms |
| 50,000 | 211.50 → 119.41 ms | 43.5% | 196.28 → 111.81 ms |
| 100,000 | 410.29 → 208.19 ms | 49.3% | 373.86 → 195.95 ms |

数字是每轮 P95 的三轮中位数。三组均通过质量检查，无回调丢失或中等以上热状态标记。deadline miss 依次为 42.62% → 31.48%、57.14% → 62.50%、56.25% → 60.00%；后两组该比例没有改善，不能以耗时降低推断长文已达到帧预算。两组帧数也会随布局与无效绘制变化，不将 miss 比例或本次 Debug 结果换算成平均 FPS。

这证明实际全屏路径的重复布局开销下降。独立全屏装饰层简化曾做探索性对照，没有证实收益，已撤回；探索数据不计入此处最终结果。当前单一大 TextField 的长文布局仍昂贵，补全有界化的性能收益也不能从本组未启用补全的负载计算。

## 功能回归

- JVM 28 项：补全的有界复制/绝对范围/边界条件，相同文本回填保留选区，10 万字及 emoji 追加，附件替换与多文本段编辑合并。
- 真机 3 项：共享状态切换保持文本/选区/undo-redo；原生 InputConnection 的组合文本跨宿主不丢失及全屏后台补全停止；长文中段全屏编辑后返回底部，选区和继续输入位置保持正确。
- Python 指标/质量检查 6 项；Debug 和测试 APK 构建通过；IME 宿主审计 A=0、A'=0，现有 B/C 告警未作为新增回归；`git diff --check` 通过。

组合输入采用原生 InputConnection 固定操作，不等于真实中文键盘完整候选流程；宿主切换会结束原窗口的 IME 会话，未承诺保留候选栏。滚动状态由外置 ScrollState 保留，当前输入框未暴露可直接断言的 VerticalScrollAxisRange，数值滚动偏移和任意手动滚动位置仍需人工验收。未覆盖旋转/进程重建、真实远程工作区补全负载及 Release 性能。
