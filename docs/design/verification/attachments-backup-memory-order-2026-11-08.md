# 发图限制、备份自校验与记忆显示排序（2026-11-08）

状态：三项已本地实现，未推送、未发版。

## 行为

- 静态图片发送仍沿用现有 EXIF 归一化与 JPEG 编码，采样边界收紧为最长边 4096、总像素 800 万。质量从 85 逐档降低，必要时再缩小，压缩后图像字节不超过 5 MiB（base64 膨胀前）。原附件不改写。GIF 不转静态图，超过 5 MiB 明确拒绝；data URL / 裸 base64 同样检查图像字节上限。HTTP 图片 URL 仍由服务端取图，本地不下载检查。
- 聊天附件导入和音视频编码上限为 100 MiB。导入按流实际字节计数，不信任 SAF 声明长度，超限原子写入失败并清理临时文件。选择器和剪贴板入口显示失败消息。供应商编码不能把大小拒绝静默跳过。
- 完整 ZIP 与增量备份都在一致性数据库副本上执行 `PRAGMA integrity_check` 和 `PRAGMA foreign_key_check`，通过后才打包/导出对象。任一失败即中止；完整 ZIP 删除本次半成品。旧 SQLite 的完整 ZIP 回退路径先复制 DB/WAL 到唯一私有目录、恢复 WAL，再校验并打包该副本，不再校验后去打包变化中的现库。旧平台回退路径本轮未在旧系统设备单独实测。
- 记忆页在“全部”筛选中提供长按拖拽手柄，拖动时仅更新本地显示、松手提交；分类筛选中不拖拽。侧边跳转条复用现有组件。空拖/落回原位不写库，失败撤销本地预览。

## 记忆排序与迁移

DB 63→64 自动迁移新增可空 `memoryentity.display_order`，存量 NULL 按原自增 id 派生顺序，避免改写历史行。`AssistantMemory.displayOrder` 是独立显示投影；现有 `sortKey=id`、DAO id 查询顺序、注入选取、打分、清单顺序不改。

新增/回收站恢复追加到显示末尾，编辑保留原位置。通常移动一行写入相邻键中点；空档耗尽时只扩展所需后缀，不压缩删除形成的空档。排序写入只改显示列，不推进业务 revision/updated_at，不覆盖遥测或锚点。落盘在事务内按稳定 id 重读与定位，不以 Lazy 列表下标写库。
