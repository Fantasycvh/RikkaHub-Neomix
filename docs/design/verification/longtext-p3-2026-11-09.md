# 长文 P3：静态内部懒加载验收

P3 基于 P2 提交 `d933e17fc` 实现。本文记录提交前的验收快照，后续提交与推送状态以 Git 为准。设计、适用范围、选择语义和恢复契约见 [实施说明](../longtext-p3-static-lazy.md)，完整数字与二进制身份见 [summary.json](longtext-p3-2026-11-09.summary.json)。

## 实现范围

标准布局的静态长消息使用原聊天 LazyColumn，后台准备完整显示文档，按安全语法单元合并为有界列表行，只排版视口附近内容。默认开启“长消息按需显示”，可在通用设置关闭。实色/隐藏气泡支持连续背景与外缘圆角；其他可见材质、其他布局、通知及本次列表展示期间生成的回复保留完整渲染路径。

逻辑索引统一处理引用、搜索/路由、上下消息跳转、压缩检查点与尾部按钮；发送后贴底等待消息身份变化，避免以消息数量猜测真实行号。阅读恢复保存小型身份/显示偏移，不将正文或解析树放入 Bundle。长正文跨行共享选择组，普通拖选不跨无关消息；源数据全选和动作栏/复制面板的完整复制不依赖离屏节点。编辑、持久化、发送和导出仍基于原始消息。

相邻小单元每行最多八个、合计最多 1024 UTF-16 字符；超大原子单元独占一行。静态正文跳过消息分组和布局注册表订阅。准备、流式结束时的宿主保留，以及选择布局通知去重，避免重复布局反馈。

## 正确性与构建

最终 Debug 和测试 APK 构建通过。最终 JVM 应用 3248 项、Markdown 模块 44 项，共 3292 项，无失败；其中应用原有两项跳过。新增 ChatRenderIndexTest 10 项覆盖逻辑索引、稳定键、检查点/分支、阅读恢复、准备/原子块回退、附件顺序、完整源片段和小单元安全合并。其他相关消息、编辑、补全与全部上游 Markdown 测试一并通过。

PJX110 / Android 15 上，最终 19 项真机测试全部通过：

- P3 新增 9 项：生产聊天列表懒加载、插入消息/字号变化时的区块锚点、引用与候选分支完整复制、后台生成时阅读位置的状态恢复、流式回复不在本次会话结束时替换宿主、源数据全选、跨片复制、不同组拖选隔离、懒加载复制面板及连续实色气泡。
- 既有长文编辑 3 项、外观 5 项、Markdown 投影 2 项。投影包含 40 份解析快照导出与独立单元/全文像素比较，最终快照与 P2 保存的原 AAR 版本 40/40 相同；图片/公式插槽使用文本替身，不能据此声明真实远程图片或 KaTeX 压测通过。
- 状态恢复使用 StateRestorationTester，验证等待异步准备后恢复区块与像素偏移；不是完整 OS 杀进程实验。普通字号调整保留区块和像素偏移，不保证同一字符的屏幕位置不变。

约 10 万字符（100889）、2000 个只读区块的全选测试中，跳到第 1000 行后首行已回收，仅 14 个活动区块，复制内容与完整源文逐字相同。全选释放行 pin，普通拖选继续沿用 BetterText pin 行为；后者极长范围仍可能保留很多行。全选时 Java heap 端点 40,841,136 → 47,618,592 bytes，PSS 395,599 → 410,135 KiB；这是包含选择/滚动/复制的单次端点观察，无强制 GC，不是峰值或严格内存上界。

设备的 FuckClip 模块拦截原生剪贴板读取，早期回读返回空并弹授权页。未修改设备权限；最终测试通过注入 Compose LocalClipboard 验证生产复制动作的实际 ClipEntry 内容，包括分支切换后的最新完整消息。生产仍使用系统 LocalClipboard。该测试验证写入载荷，不声称绕过或验证 ROM 的读取权限。

早期测试还发现选区全局布局回调无条件递增状态造成反馈循环，以及生成贴底已到目标仍重复请求布局。前者改为比较实际几何/布局身份，后者只在未贴底时请求；最终选择、生成与恢复测试均通过。测试中实色气泡接缝要求一致，外圆角边缘允许 Android 两种轮廓抗锯齿最多 0.16 通道误差。

宿主基线脚本 6 项通过；IME 审计 A=0、A'=0，既有 B=4、C=32 告警；差异空白检查通过。

## 最终静态性能矩阵

同一设备、默认外观、请求 60Hz、动画开启、离线固定样本，每种内容/长度独立新进程、各 3 轮。数值为逐轮指标的中位数，首绘帧排除。before 原样重放 P2 已归档 application/test APK 配对；after 使用最终分组实现。两侧各 27 行，全部无质量告警、无回调丢失，热状态均为 0。

| 内容 | 字符数 | 帧 P95 前 → 后 | deadline miss 前 → 后 |
|---|---:|---:|---:|
| dense | 10000 | 16.26 → 24.81 ms | 3.85% → 8.40% |
| dense | 50000 | 23.82 → 26.10 ms | 6.82% → 6.87% |
| dense | 100000 | 24.43 → 26.93 ms | 8.89% → 8.33% |
| mixed | 10000 | 24.06 → 29.55 ms | 12.32% → 10.77% |
| mixed | 50000 | 32.18 → 32.80 ms | 20.93% → 5.93% |
| mixed | 100000 | 45.03 → 31.10 ms | 20.31% → 6.87% |
| prose | 10000 | 17.70 → 34.74 ms | 4.55% → 6.67% |
| prose | 50000 | 17.62 → 20.99 ms | 4.65% → 7.75% |
| prose | 100000 | 20.33 → 29.61 ms | 10.08% → 4.62% |

收益集中在长篇复杂混排的内存、deadline miss 及 10 万字 P95；不能概括为全面帧率提升。普通段落 P95 仍有回退，较短 mixed 也没有 P95 收益；dense 是不拆分的原子单段回退，不期待本阶段解决。保留开关供真实使用对比和回退。

mixed 5 万/10 万字的稀疏采样 Java heap 峰值分别为 149.75 → 41.99 MiB、288.03 → 38.30 MiB。完整源码与 AST 仍在内存中，收益来自减少离屏 UI 布局。稳态滚动期间仍会分配新可见内容：mixed 10 万字 ART 分配量中位数 2.35 → 4.07 MiB，prose 5 万字 2.22 → 3.08 MiB，GC 中位数均为 0；这体现首次全文排版与滚动时逐步排版的成本转移，不宣称所有分配都下降。

虽然窗口报告刷新率相同，Android 每帧 deadline 在约 16.67/33.34ms 间变化，两个版本的分布也有差异。汇总 JSON 保留每轮预算分布；P95 与 deadline miss 不能互相代替，也不能直接换算为用户平均 FPS。Debug/JIT、OEM 调度与负载差异仍可能影响结果。

额外使用旧 P2 与最终 P3 APK 配对各三轮，运行 5 万字 mixed 流式回放加滚动：帧 P95 192.14 → 162.62ms，deadline miss 12.94% → 10.42%，全部质量检查通过。该路径保持完整回复渲染，用于兼容冒烟，不代表已经实现流式懒加载或端到端模型性能；仍有明显长帧，留到 P4。
