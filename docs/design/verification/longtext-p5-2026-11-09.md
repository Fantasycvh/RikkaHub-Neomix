# 长文 P5：超大单块与分段编辑验收

基于 `2457fb826`，保留后续气泡/纹理/shader 工作。本记录为提交前的验收快照，后续提交与推送状态以 Git 为准。实现、阈值、编辑语义及限制见 [实施说明](../completed/longtext-p5-large-atoms.md)。

## 根据测量作出的选择

完整排版普通超长纯段落的滚动已相对便宜；折叠探索中 dense 的 P95 27.07 → 32.07ms，没有证实收益。因此最终纯文本 Paragraph 保持完整显示。复杂原子块超过 24000 UTF-16 字符默认显示有标注的原文预览（最多 3000 字符/64 行），提供完整原文阅读/复制及显式完整排版入口。AST 与原始消息不被截断，既有流式单元跨阈值保持展开。

当前 HEAD 三轮 10 万字实际全屏切换输入 P95 为 127.05ms，仍偏高，因此增加可选分段草稿。每次一个常驻 TextField，初始每段最多 4096 字符，按原光标所在段进入；允许插入空白段，不设隐藏输入上限。应用才合并全文，取消保留原文；外部变更或编辑目标变化拒绝旧草稿覆盖。原全文模式保留。

## 最终正确性

最终 Debug 与测试 APK 构建通过。应用 JVM 3262 项、Markdown 44 项，无失败，应用原有两项跳过。25 项真机回归通过，包括超大代码块预览后完整原文复制、生成区块跨阈值不突然折叠、分段编辑的未完成中文组合输入跨段、取消及全文合并，以及既有引用/分支/恢复/外观/全屏编辑/Markdown 投影。

源文本、代理对/CRLF 边界、光标、插入空白段和外部源更新冲突由 JVM 测试检查；分段应用前原文逐字不变。IME 宿主审计 A=0、A'=0，原有 B=4/C=32 告警，差异空白检查通过。P0 主机脚本 6 项通过。最终 40 份解析快照与原 AAR 版本相同。剪贴板沿用 LocalClipboard 捕获写入载荷，不修改 ROM 权限。

## 滚动与内存

PJX110 / Android 15，Debug，默认外观，请求 60Hz，离线样本，每种内容 100000 码点，各三轮，新进程按 fixture 隔离。before 为当前 HEAD 重建的 APK，after 为最终纯段落豁免策略。两侧各 12 行、全部质量检查通过。指标为逐轮 P95/端点或稀疏采样指标的中位数，首绘排除。

| 内容 | 帧 P95 前 → 后 | deadline miss 前 → 后 | 采样 Java heap 峰值前 → 后 |
|---|---:|---:|---:|
| dense | 27.07 → 23.39 ms | 9.45% → 13.18% | 25.71 → 25.65 MiB |
| code | 30.39 → 29.03 ms | 6.72% → 6.30% | 36.24 → 27.29 MiB |
| list | 33.05 → 28.83 ms | 17.97% → 6.77% | 76.89 → 31.29 MiB |
| table | 58.22 → 28.47 ms | 24.39% → 7.75% | 187.65 → 27.07 MiB |

code/list/table 的 after 使用默认折叠预览，和 before 的完整富文本表示方式不同；不能声称完整十万字表格等价渲染变快。dense 保持完整正文。显式展开仍可能昂贵；首次完整解析、全 AST 和源码、其他不可分块布局/材质及导出不受此预览路径保护。Java heap 是稀疏工作负载采样，不是精确峰值；PSS 只记录端点。没有统一 FPS 提升结论，Android deadline、JIT/OEM 调度和短测波动仍影响结果。

## 编辑测量范围

最终 10 万字文档：原全文实际切换路径输入至绘制 P95 130.60ms，分段本段 24.14ms。分段样本初始活动段字符数 [1696]、总段数 [25]（从原光标所在的末段进入）。此前当前 HEAD 全文样本为 127.05ms。

两种模式仍通过真实 InputConnection，在各自实际 Dialog Window 上测量选区与提交；分段的首/中/尾指当前段，全文指整个文档，宿主及工作集不同，不计算相同比位点或端到端降幅。分段直接挂载全屏模式，全文经 ChatInput 切换。跨段导航、初始切换、全文合并及其一次性成本未计入稳态输入指标。局部撤销保留在草稿会话，应用后不保证旧全文撤销历史，进程杀死恢复不在本轮覆盖。
