## 二、发布流程（固定）

1. bump versionCode（`app/build.gradle.kts`，**续增不重置**；259 已用）；**设备已装 release 版时不能原地复用同号，必须递增**（否则 `INSTALL_FAILED_VERSION_DOWNGRADE`）。
2. `bash scripts/build.sh release`（自动改名 arm64 产物到 `app/release/`；勿用 `-Pandroid.injected.build.abi`，OOM 用脚本内置 `--max-workers=2`）；**ZCode 会话须带 `GRADLE_OPTS="-Djava.net.preferIPv4Stack=true"`**（修 `FileLockContentionHandler` BindException）。
3. aapt 验证 versionCode/架构；**`app/release/` 可能残留同名旧 APK，务必先核实 versionCode 再上传**。
4. debug 先装机实测 → 草稿：新建用 `gh release create vX.Y.Z --draft -R androidrik/rikka2-my_feature_open`；**替换既有草稿同名 tag 的资产**用 `gh release delete-asset --yes` + `gh release upload` + `gh release edit --title/--notes-file`（双语 ≤10 条日志，`--notes-file` 需绝对路径）。
5. 用户检查后 `gh release edit --draft=false --latest`（**tag 指向转正那一刻的分支 HEAD**）。
6. **tag 一律带 `v` 前缀**（旧 release tag 多数**不带** v，删除时须用实际 tag 名）。
7. README 下载标注随发布更新（有草稿时写「正式发布 X，草稿 Y」；无草稿只写正式发布）。
